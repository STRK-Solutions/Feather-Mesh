# W8 staged edge acceptance

This recipe prepares the existing `613202690.xyz` zone for an explicitly approved
staging run. It does not activate the initial cohort, open a public route, send
invitations, enable inference or change Cloudflare when its local checks run.
W8 acceptance requires real Access and Ubuntu results in addition to these tests.
Keep the durable edge state separate from disposable compute and research storage.

For the active Ubuntu functional milestone, leave `provisioned_sites=["ubuntu"]`.
The default creates no cloud connector or configuration, and rejects selecting
an absent site. Instructions below concerning a second tunnel apply only to a
previously provisioned cloud tunnel retained while shelved, or future resumed
cloud work. The 2026-09-25 takeover inventory found no tunnels to preserve.

## Local checks

ownership receipts, distinct groups, the two manual site selections and retained

be installed using the committed lock file, without changing its version.

connection. The connection does not provide an environment credential to Terraform

The operator's read-only inventory on 2026-09-25 reported three managed zone phases:
`http_request_sanitize`, `http_request_firewall_managed` and `ddos_l7`. No

Account MFA was initially reported disabled; after owner setup, a subsequent

The exact policy is:

| Surface | Allowed group | Application lifetime | Additional origin authority |
| --- | --- | --- | --- |
| `feam.613202690.xyz` | Recorded user group | 8 hours | Active local account; owner-only workspace actions |
| `admin.613202690.xyz` | Recorded admin group | 1 hour | Active local admin; fresh same-origin CSRF and exact reviews for mutation |

Each host has its own Access application and distinct audience. Every application

Import existing FEAM resources before planning replacements. Never import or alter

### HTTPS redirect ownership

`cloudflare_ruleset.https` creates a single rule whose expression lists only the
exact portal, admin and recorded workspace hosts. It redirects HTTP to the same
HTTPS host/path, preserves the query, and does not affect the zone apex or other
subdomains. The v5.22 provider manages an entire phase entrypoint; it has no
independent rule resource. Thus `manage_https_redirect=true` requires a reviewed
inventory proving that the Single Redirect entrypoint is absent or exclusively
FEAM-owned. Store the inventory hash in `redirect_ownership_receipt_sha256`.

If that phase contains unrelated rules, stop this apply and prepare an independently
reviewed coexistence change. Do not delete them or claim their ownership in this
module. Once created, keep `manage_https_redirect=true` even when disabling the
site: the ruleset has `prevent_destroy`. A receipt hash is an operator record,
not an automatic proof of approval. The implementation follows the
[Single Redirect API phase model](https://developers.cloudflare.com/rules/url-forwarding/single-redirects/create-api/)
and the [pinned provider schema](https://raw.githubusercontent.com/cloudflare/terraform-provider-cloudflare/v5.22.0/docs/resources/ruleset.md).

Start with `selected_site="disabled"`. There are no demo DNS records and every
Ubuntu/cloud ingress returns 404. After the actual identity, storage, budget and
archive gates pass and the operator approves the saved exact plan, provide the
reviewed `activation_receipt_sha256` and select exactly one site. Review that the
plan changes only the recorded FEAM apps/policies/tunnels/DNS and the reviewed
redirect entrypoint. Do not use `-target` to bypass preconditions.

## Install the connector without activation

[edge.yml](ansible/edge.yml) installs a dedicated `feam-edge` UID/GID **2109**,
separate from the seven runner/application identities. It has no login shell,
home directory or supplementary groups. Existing name/UID/GID collisions are
rejected before account creation. The inspected Ubuntu host assigns 2108 to
`feam-deploy`; 2109 was free at inspection and must be rechecked at apply time.
First review and apply the W7 service manifest
with `feam_gateway_frontend_uid: 2109`; its root helper owns the browser socket
ACL and must remove the previous frontend grant. This is a deliberate transition
from the private test operator identity, not permission to expand socket access.
The edge role refuses a different installed `runtime.json` frontend identity.

The native Linux amd64 binary is pinned to **2026.9.3**, published 2026-09-24:
40,122,749 bytes, SHA-256
`77e26d8d900e0b8469f416239d14b5f296525fdf79fee6f511ef55609e3fbac2`.
Both the official release asset metadata digest and release-body checksum agree.
On MAC, the exact official artifact was downloaded into private temporary storage,
its byte count/hash and ELF64 x86-64 header verified; it was not executed or
installed. Source: [Cloudflare's release](https://github.com/cloudflare/cloudflared/releases/tag/2026.9.3).
Future updates require a newly reviewed pin and maintenance stop; there is no
floating download or automatic binary update.

The fixed root helper [edge_preflight.py](scripts/edge_preflight.py) downloads only
that object, follows at most three redirects to official GitHub asset hosts, caps
bytes at the pinned size, checks SHA-256 and atomically publishes without replacing
an unfamiliar artifact. Its elapsed budget is 180 seconds, with a 15-second
individual network-read timeout; one pending read/DNS operation can outlive the
elapsed check. It never extracts an archive. The executable is root-owned 0555
under `/opt/feam/edge`, and is rehashed at every connector start.

After the reviewed UID transition, inspect the disabled install plan:

```sh
ansible-playbook -i /private/operator/inventory.yml infra/demo/ansible/edge.yml --check
```

The separately authorized installation uses the same command without `--check`.
It defaults to `feam_edge_start=false`, `feam_edge_enable=false` and
`feam_edge_activate=false`; no Tunnel token is required for disabled installation.
Changing a running connector is refused unless `feam_edge_stop=true` explicitly
authorizes stopping it first. No role creates DNS, Access resources or public ports.
It installs only on the recorded Ubuntu 24.04 x86-64 target.

For later activation, put these nonsecret inputs in a private reviewed vars file:

```yaml
feam_edge_account_id: RECORDED_ACCOUNT_ID
feam_edge_tunnel_id: RECORDED_SELECTED_TUNNEL_UUID
feam_edge_readiness_sha256: SHA256_OF_REVIEWED_READINESS_RECORD
feam_edge_token_source: /root/feam-private/selected-tunnel-token
feam_edge_activate: true
feam_edge_start: true
feam_edge_enable: false
```

The token source is a host-local root-owned 0600 regular file, at most 16 KiB;
its contents are never an Ansible variable, command argument or Terraform output.
The role copies it with `no_log`/no diff to `/etc/feam/edge/tunnel-token` under a
0700 parent. The start guard checks the encoded account/tunnel and rejects an
alternate endpoint. systemd `LoadCredential` supplies a private read-only copy to
UID 2109; the connector itself cannot read the root source or other services'
configuration. It uses the official [token-file option](https://developers.cloudflare.com/tunnel/reference/run-parameters/).
There is no account-wide certificate, Terraform credential or model key in this
service. The connector has no Linux capabilities or writable service data; its
only HTTP listener is metrics on `127.0.0.1:20241`. It uses outbound HTTP/2 transport,
warn-level logs and 256 MiB memory/no swap. Do not enable debug request-header logs.

Startup requires the exact private readiness record, binary, dedicated identity,
tunnel token and installed gateway browser socket owned by UID 2102. The root
preflight checks the kernel's actual socket permission as UID 2109 with cleared
supplementary groups. The connector cannot start successfully on an old operator
ACL. The narrowly fixed root preflight runs separately from the unprivileged
connector; no browser input controls its paths or arguments.

Only after the saved edge plan and staged activation are authorized, apply the
reviewed vars file with `ansible-playbook ... -e @/private/operator/edge-active.yml`.
Then verify the real systemd credential sandbox, socket ACL, connector version,
loopback metrics binding and absence of other listeners on Ubuntu. Local syntax,
lint and fixtures do not prove these host properties. This session has not applied
the edge role, started a connector or exposed a route.

## Match Access to the installed gateway

Export `terraform output -json audiences` and `terraform output -raw issuer` from
the durable edge state into private configuration. Match every host/audience pair
to the installed gateway/controller configuration. The gateway requires an exact
`https://TEAM.cloudflareaccess.com` issuer, RS256, one exact application audience,
expiry and issued-at, type `app`, subject and email; it rejects multiple audiences,
remote JWT key URLs and excessive lifetime. It ignores forged identity email
headers. Its signing certificate fetch is bounded and follows no redirects.

Each selected tunnel ingress additionally sets Access `required=true`, the same
team name and only that host's audience. The target is the private Unix socket
`unix:/run/feam/services/gateway/browser.sock`; no browser TCP listener is published.

The connector uses explicit QUIC transport. The deployed HTTP/2 transport
returned 502 on WebSocket upgrades to this Unix origin with `no Host in request
URL`, while ordinary authenticated HTTP worked. This matches
[cloudflared issue 560](https://github.com/cloudflare/cloudflared/issues/560).
Verify outbound UDP 7844 connectivity, connector readiness and an actual
authenticated WebSocket after installation; an HTTP page alone is insufficient.
Keep the Unix origin and exact Access audiences intact. Cloudflare documents
the transport flag and port in its [run parameters](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/run-parameters/)
and [firewall guidance](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/tunnel-with-firewall/).
A final unmatched `http_status:404` rule is required on both tunnels. Verify the
actual API snapshot, not only a Terraform plan. These checks follow Cloudflare's
[JWT validation guidance](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/)
and [Tunnel Access origin settings](https://developers.cloudflare.com/tunnel/reference/origin-parameters/).

For managed HTTPS, verify the actual certificate covers each first-level sibling
host, the chain is trusted and Universal SSL is active with automatic management.
Do not infer coverage for nested names or disable TLS verification in probes.
Record certificate expiry/status and renewal ownership separately; a successful
TLS connection today does not prove a future renewal. The probe uses the system
CA store and exact SNI/hostname validation on every HTTPS request.

## Run the bounded admission probes

Copy [the example](tests/edge/config.example.json) to a private directory and replace
fixture issuer, audiences and workspace hosts with recorded values. Files must be
owned by the invoking UID and mode 0600; symlinks and oversized files are rejected.
Use actual application assertions obtained by the approved staging testers through
Access. Never paste them into chat, command arguments, public JWT sites, evidence
or the repository. Each token file contains only the assertion. Remove unavailable
token entries; their corresponding cases remain failures, not silent skips.

Token names distinguish host and identity. `workspace` is the first owner's token;
`other_workspace` is the second owner's token for their own workspace;
`cross_user` is the second user's token for the first workspace's audience. The
coarse Access user policy may issue the latter, while the local owner check must
deny it. Both owner requests must succeed. `disabled_workspace` belongs to a
disabled test identity, with an otherwise unexpired token for the first workspace.
`expired_workspace` must be genuinely expired with its original signature.
The suite never mints provider signatures or assumes a tampered token proves actual
expiry. Keep an old signed assertion privately until its expiry gate is testable.
An admin token belongs to the admin application; the wrong-audience terminal probe
must deny it. Do not broaden participant membership to mint admin terminal tokens.
The gateway's same-audience admin denial is additionally covered by its local tests.

From the external MAC staging browser machine, using absolute private config paths:

```sh
python3 infra/demo/tests/edge/probe.py --mode public --config /private/operator/edge-probe.json > /private/operator/w8-public.json
python3 infra/demo/tests/edge/probe.py --mode origin-ports --config /private/operator/edge-probe.json > /private/operator/w8-origin-ports.json
```

Run `origin` on UBUNTU as the authorized socket operator, using local owner-only
copies of the necessary private token files. Do not relax socket ACLs for the test:

```sh
python3 infra/demo/tests/edge/probe.py --mode origin --config /private/operator/edge-probe.json > /private/operator/w8-origin.json
```

Public mode sends `CF_Authorization` cookies; origin mode sends the actual
`Cf-Access-Jwt-Assertion` directly over the fixed Unix socket. This separation
prevents Cloudflare's cookie handling from masking gateway JWT validation. The
suite covers missing/forged identity, modified/unsigned/expired tokens, distinct
host audiences, disabled accounts, cross-user ownership, exact-route 404, positive
HTTPS WS upgrade, missing/sibling WS Origin and sibling POST Origin. The POST has
an empty body and no action/CSRF/confirmation, so cannot mutate a workspace.
WS probes close immediately after a validated handshake and send no terminal input.
No response bodies, cookies, JWTs or emails enter the receipts. Missing tokens,
network/protocol failures, 5xx and unexpected redirects fail the suite. Redirects
are not followed; denied public login redirects must target the exact team issuer.
Only the HTTP-to-HTTPS probe uses port 80, and it sends no credentials.

Each response header is capped at 32 KiB with an eight-second deadline; the suite
has a 180-second dispatch deadline. DNS resolution also depends on the operator
OS resolver's timeout. Run from a known healthy network and retain failed attempts.
An exit status of zero means the selected mode's checks passed. It does not cover
PIN delivery, certificate renewal, live revocation timing or model acceptance.

`origin-ports` attempts only ports 80, 443, 7681, 8080, 2375 and 2376 on the single
explicit `origin_ip`; it never scans SSH or a network range. Run for each recorded
public IPv4/IPv6 address from the intended external vantage point. Refusal or
timeout shows unreachability from that point only. Pair it with private host
`ss -lntp`/firewall/container-port inspection proving no FEAM browser, ttyd or Docker
TCP listener is published; preserve unrelated host services. A network-route error
is unverifiable, not a pass. No public SSH is required by the demo. Do not close an
existing operator management route as part of this probe.

## Manual deployment switch

A switch is an operator action, never automatic recovery. First stop admission and
model dispatch on the old deployment, drain/reconcile unknown work, flush research
and spending records, and record the durable project-ledger/activation transition.
Select `disabled` and verify both tunnels deny; retain applications/audiences,
redirect configuration and operator state. Stop the old connector and invalidate
its deployment capabilities before activating a replacement. DNS propagation or
an Access policy update alone does not fence the old runtime.

Recreate and verify the target using W7's ledger seed/new activation process; import
no old runtime DB as current authority. Then review the exact switch plan with a
new readiness receipt, select the one target, start its recorded connector and run
this complete edge acceptance again. The unselected tunnel must still deny every
route. Existing applications/audiences remain stable because they are independent
of `selected_site`. Retain evidence that a stale connector, cookie, account version,
workspace generation and model capability cannot regain authority. Do not destroy
edge state or the research bucket when removing disposable compute.
