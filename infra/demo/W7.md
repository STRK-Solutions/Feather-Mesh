# Private participant services

The executable operator start/stop, archive verification, budget closure and
next-run rotation recipe is [SITE_LIFECYCLE.md](SITE_LIFECYCLE.md).

The [services playbook](ansible/services.yml) installs reviewed native artifacts,
private configuration, separate systemd services, bounded runtime storage and
fixed Unix ACLs. Its default installs configuration without starting application
services, initializing databases or enabling boot startup. The existing W1
playbook still selects its original private operator service. Neither entrypoint
creates a public route or authorizes live inference.

This recipe has local configuration, template, syntax and lint evidence. It has
not yet established Ubuntu service identities, reboot ordering, repeat converge
or fresh-VM acceptance. Those require the actual target checks below. Consult
the [workplan](../../docs/ubuntu_web_dev_demo_workplan.md) for remaining gates.

## Reviewed prerequisites and inputs

Provision the seven fixed service identities and reviewed storage pool first.
`operations`, `traces` and `datasets` must be mounted at
`/home/feam-service-data/` with their recorded filesystem UUIDs. The services
role refuses a missing or different filesystem. It does not format, adopt or
erase storage. Fresh controller initialization also refuses occupied slots;
retained W1 bytes require their separate explicit retention/reclamation review.

Build Go artifacts with [native_web_build.sh](scripts/native_web_build.sh) and
Rust `feam` with [native_build.sh](scripts/native_build.sh). Both extract a
verified source archive into its own immutable digest-named directory; a later
build cannot retain files removed from source. Verify the resulting artifact
hashes before preparing private variables. A release directory already holding
a different binary is rejected instead of overwritten.

Install the pipeline's pinned interpreter, locked wheels and reviewed converter
using [pipeline-tools.yml](ansible/pipeline-tools.yml) before admitting dataset jobs.

`infra/demo/images/terminal/requirements.lock`), `feam_pipeline_converter_source`
(the corresponding `web_demo/importers/convert.py`), and their exact
`feam_pipeline_lock_sha256`/`feam_pipeline_converter_sha256` values.
The scoped installer checks hashes before downloading, uses native Python 3.12
and hash-locked wheels, records a versioned root-owned installation, and atomically
selects its fixed links. It preserves previous installations and refuses unknown
paths or incomplete prior attempts. Downloads have a ten-minute process timeout.

dependencies fail rather than changing its package installation implicitly.

`.incomplete-ensurepip` archive before retrying; an existing archive or any

The fixed paths are `/opt/feam/pipeline/bin/python` and

## Ownership, mounts and resource bounds

| Process | UID | Writable persistent state |
| --- | --- | --- |
| Rootless runner | 2101 | Separate runner storage from the runtime role |
| Gateway | 2102 | `operations/gateway` |
| Controller | 2103 | `operations/controller` |
| Broker | 2104 | `operations/broker` |
| Collector | 2105 | `traces/collector` |
| Pipeline | 2106 | `datasets/pipeline` |
| Reconciler | 2107 | `operations/reconciler` |

Service binaries live under `/opt/feam/services/RELEASE_SHA/`, root-owned and
non-writable. JSON and secrets live in each private
`/etc/feam/services/SERVICE/` directory. The project encryption/signing keys and
US$100 project ledger stay outside compute; only the finite signed allocation
and verification public key reach the broker.

`run-feam.mount` creates a 32 MiB `nodev,nosuid,noexec` tmpfs.
`feam-service-runtime.service` verifies each service and recreates private runtime
directories before `user@2101.service` or participant services. The runtime role
must install its participant runner dependencies before service activation.
The controller still decides which workspace containers may run; their Docker
restart policy remains disabled.

Control sockets use `/run/feam/services/SERVICE/control.sock`. Gateway browser
traffic uses `/run/feam/services/gateway/browser.sock`. Each workspace gets:

| Directory under `/run/feam/workspaces/UUID/` | Owner and named access |
| --- | --- |
| `terminal/` | Mapped container UID 200999; gateway/controller named access; runner traversal |
| `model/` | Broker; mapped container connects only `broker.sock`; runner traversal |
| `events/` | Collector; mapped container connects only `events.sock`; runner traversal |
| `config/` | Controller writes; mapped container reads; runner traverses |

Named ACLs never grant the owning group or others access. A stat mode of 0640 on
a capability can represent its named read ACL mask; verify `getfacl` shows
`group::---`, `other::---`, and only mapped UID 200999 as the extra reader.
Each service startup reconciles only stale sockets it owns, refuses an active or
foreign listener, then installs exact peer ACLs after bind. Peer UID checks also
run inside HTTP handlers; socket permissions alone are not authorization.

Application units have a read-only system/home except explicit state/runtime
paths, empty capabilities, no new privileges, private devices/tmp, bounded file
descriptors/tasks, and no swap. Control services share a 2 GiB/200% CPU slice;
the pipeline has a separate 2 GiB/100% slice. Units bound journal bursts and
restarts. The dedicated runner has its own aggregate limits in the runtime role.
The optional `feam-service-health.timer` performs read-only mount/config/artifact
checks and connects to the owned sockets of active services. It reports basic
liveness, not database/application readiness, and never starts or restarts a
service. Intentionally inactive services stay inactive. Enable it only with the
explicit service boot opt-in; stop the timer as part of intentional site stop.

```sh
ansible-lint --offline infra/demo/ansible/services.yml infra/demo/ansible/roles/services
```

After reviewing the concrete private inputs and authorized target scope:

```sh
ansible-playbook -i .local/demo-deployment/inventory.yml infra/demo/ansible/services.yml -e @.local/demo-deployment/service-vars.yml
```

The first call installs the private mount/layout/units; application start and
database operations remain off. Install the participant runner ordering next.
Explicit initialization selects only brand-new databases, while the named
service is inactive. The deployment account's passwordless sudo targets root;
the reviewed command then uses `/usr/sbin/runuser` to drop to the fixed service
owner for initialization and migration. Direct `sudo -u feam-SERVICE` from the
deployment account is not authorized on the current host. Include
`feam_services_initialize` in a separate reviewed
private variable file, for example `[gateway, controller, broker, collector,
pipeline]`. Never keep that list in repeat-converge input. A partial failure is
reviewed as partial state; rerunning initialize does not silently adopt it.

For a reviewed schema transition, stop the selected services and set only
`feam_services_migrate` (`gateway`, `controller`, `collector`, `pipeline` currently expose
explicit migration commands). The broker currently has its first
schema and no migration CLI; incompatible source/schema hashes fail closed.
Retain previous binaries and state evidence. Never downgrade a newer database
with an older binary or silently reinitialize it.

Set `feam_services_start: true` only after activation/configuration review and
runner ordering are installed. `feam_services_enable` is a separate explicit
choice. Repeat converge uses empty initialization/migration lists and restarts
only components whose units/configuration changed, plus helper-affected units.
Missing state, budget, policy, mount or hash is a startup failure.

## Drain and retention

The controller identity can `POST {}` to the broker control socket at
`/v1/run/drain`. The broker pauses admission durably, cancels active/queued calls,
waits at most 30 seconds for accounting, marks unresolved requests unknown and
checkpoints SQLite before returning/writing `feam.broker-drain.v1` to its private
configured receipt file. A timeout/error does not produce a successful new receipt.
SIGTERM also cancels, joins accounting and checkpoints before bounded HTTP
shutdown, but preserves the prior admission state for an ordinary service/OS
restart. It never unpauses a run that was explicitly drained or paused at a limit.

The receipt includes allocation digest, deployment/generation, aggregate costs
and unknown counts. It has `broker_observed` provenance and is not independent
proof of final provider charges. Every unknown keeps its reservation. The
operator reconciles verified charges against the off-host ledger before closing
the run; failed or lost receipts cannot replenish funds. An explicitly drained
run stays paused across restart. Ordinary service/OS restart can continue an
active run only within its existing allowance and current authority; unknown
requests cannot replay or replenish it. The controller still enforces desired
running/stopped state and current grants after boot.

Collector flush and verified durable archive receipts are separate gates. Stop
public admission, stop/revoke workspace capabilities, drain, preserve receipts,
flush/archive and verify retained hashes before destructive teardown. A failed
archive or unresolved accounting blocks deletion of its source. The service
playbook has no destructive teardown path; use the reviewed lifecycle entrypoint
and keep durable edge/research resources separate from disposable compute.

## Target acceptance still required

The existing W0 guest is only 16 GiB. The separate
[integration VM manager](scripts/integration_vm.py) prepares a fresh guest under
the owned W0 parent's `w7-integration/` directory, reusing its verified base image
and extracted QEMU tools. It never modifies the W0 disk or host packages/services.
Its limits are two TCG vCPUs, 4 GiB RAM, a 384-GiB logical disk and localhost SSH
port 22372. Host admission reserves room for the disk maximum plus the physical
host's own storage floor, and requires 6 GiB available RAM before start.
This is a functional fault-test guest, not a ten-user performance target.

After the exact helper/probe transfer is authorized, run as the original Ubuntu
build owner in the reviewed source directory:

```sh
python3 infra/demo/scripts/integration_vm.py prepare --probe infra/demo/tests/full_vm_probe.sh
python3 infra/demo/scripts/integration_vm.py start
python3 infra/demo/scripts/integration_vm.py status
ssh -p 22372 -i ~/feam-w0-vm/w7-integration/guest_access \
  -o StrictHostKeyChecking=yes -o UserKnownHostsFile=~/feam-w0-vm/w7-integration/known_hosts \
  feamtest@127.0.0.1
python3 infra/demo/scripts/integration_vm.py stop
```

Preparation/start are explicit; neither is an automatic fallback for a failed
service. Existing/partial guest disks are never reinitialized. Guest dependency
