# W1 private terminal operator runbook

W1 is a private operator smoke slice. The production participant gateway and
lifecycle controller are W2/W3. [Execution status and attempts](../../docs/evaluations/web-demo/w1-progress.md)
are authoritative; these commands alone are not evidence that a host passed.

## Local validation

Use the isolated pinned Python environment from [the baseline](README.md):

```bash
python infra/demo/scripts/check.py
python -m unittest discover -s infra/demo/tests/w1 -p 'test_*.py' -v
```

From `web_demo/`, with Go 1.27.1:

```bash
go test -race ./...
go vet ./...
go build -trimpath ./cmd/private-terminal
```

The checks do not connect to an inventory or run privileged probes. CI runs the
Go checks on native Ubuntu. Full-system mount/boot/container evidence is separate.

## Finite runtime and storage

The W1 scope is `/home/feam-service-data`, seven `feam-*` system identities at
UID/GID 2101–2107, runner subordinate IDs 200000–265535, two 2-GiB ext4 slots,
a 20-GiB runtime filesystem (4 GiB only for the small disposable VM), and a
1-MiB/64-inode socket tmpfs. This is the one-terminal slice; W3 introduces the
full ten-workspace pool. Container UID/GID 1000 maps to host 200999. Root-owned
records pin backing-file device/inode/size/UUID; interrupted/unrecognized files
require explicit reconciliation. No recorded file is formatted on converge.
New files finish inode-table and journal initialization before mounting, then
reassert their full allocation. `nodiscard` alone does not prevent lazy inode
zeroing from releasing loop backing blocks. Completed initialization is recorded
once in the root-owned inventory; legacy W1 records are flushed and checked
before that marker is added. Admission requires the marker, UUID, backing
identity and full allocation, without scanning live allocation bitmaps.
Allocating holes never changes existing filesystem bytes.
The [disposable reservation regression](tests/w1/storage_reservation.py) proves
both the original failure and inode/UUID/data preservation during repair.
See the [mke2fs initialization options](https://www.man7.org/linux/man-pages/man8/mke2fs.8.html)
and [kernel loop zeroing implementation](https://github.com/torvalds/linux/blob/master/drivers/block/loop.c).

The runner uses a lingering **user** Docker service, private data root and
`/run/user/2101/feam-docker.sock`. Only its controller identity receives socket
access. The system user-manager instance requires and binds to the host mounts;
its root pre-start checks verify filesystem identities and recreate socket ACLs.
Converge verifies logind's live `Linger=yes` registration; the linger file alone
is insufficient after a failed startup. The disposable
[lingering recovery probe](tests/w1/linger_recovery.py) tests re-registration
without login and restores the same terminal generation.
The gateway gets only the terminal socket; sibling service accounts do not.
The dedicated runner slice bounds aggregate CPU, memory/swap and task counts.
No existing system Docker service, data root or global namespace policy is edited.
Ubuntu's packaged RootlessKit allowance is retained; per-container AppArmor is
not claimed. See [Docker's rootless service/cgroup guidance](https://docs.docker.com/engine/security/rootless/tips/)
and [Ubuntu prerequisites and limitations](https://docs.docker.com/engine/security/rootless/troubleshoot/).

Before a physical-host apply, refresh the read-only inventory and install only
its reviewed missing dependencies. I1 records that the owner runs privileged
bootstrap. Do not substitute the sanitized example UUID or relax host policies.

```bash
ansible-playbook -i PRIVATE_INVENTORY infra/demo/ansible/host.yml
ansible-playbook -i PRIVATE_INVENTORY infra/demo/ansible/host.yml
```

Required inventory inputs: exact `feam_parent_uuid` from `findmnt -T /home`,
strictly verified SSH target/key, and optional `feam_runtime_mib: 4096` only for
the disposable guest. Production defaults to 20480 MiB. The host playbook checks
that uidmap, ACL, user D-Bus, AppArmor and Docker rootless extras are installed;
it never replaces the physical host's Docker packages. No reboot is performed.

For the owner-run physical bootstrap, package the reviewed source and exact
tested native artifacts before requesting sudo:

```bash
python infra/demo/scripts/build_w1_bundle.py \
  --image /PRIVATE/terminal-image.tar --proxy /PRIVATE/private-terminal \
  --operator-json /PRIVATE/operator.json --output /PRIVATE/new-owner-bundle.tar
sudo bash infra/demo/scripts/owner_bootstrap_w1.sh \
  --reviewed-bundle /PRIVATE/new-owner-bundle.tar PRINTED_SHA256
```

The private operator JSON has exactly `feam_parent_uuid`, `feam_operator_uid`,
`feam_image_id`, `feam_proxy_sha256`, `ansible_bin` (the retained locked venv's
bin directory) and `operator_output_dir` (an existing owner-only directory).
Use the [tested artifact pins](../../docs/evaluations/web-demo/w1-artifacts.json).
Each bundle has a new filename and hash; retain earlier failed attempts.

The entrypoint installs only the reviewed missing uidmap prerequisite, verifies
a root-owned source copy, converges, loads the image if absent, deploys, then
runs the fixed private acceptance phases. Successful phase markers and failed
logs remain under the root-owned `w1-acceptance` directory. Reruns reuse completed
phases; an interrupted reset must be reconciled before resuming. Final checks
require unchanged converge, live lingering with no login sessions, and preserved
unrelated Docker/namespace/AppArmor state. Evidence and the private browser
credential are exported to the owner directory without printing the credential.
The [execution record](../../docs/evaluations/web-demo/w1-progress.md) contains
the exact final v4 command/hash and the resolved earlier failures.

## Image and native proxy

The terminal recipe is [images/terminal/Dockerfile](images/terminal/Dockerfile).
It pins the amd64 Ubuntu base, W0 hosted FEAM binary, ttyd 1.7.7 and exact Python
wheel URLs/hashes. The build generates fixtures and installs the supported SDK.
No package installation happens inside a running participant container.

```bash
python infra/demo/scripts/build_terminal_context.py \
  --feam /PRIVATE/native-feam --ttyd /PRIVATE/ttyd.x86_64 \
  --output /PRIVATE/new-build-context
docker build -t feam-terminal:w1 /PRIVATE/new-build-context
docker image inspect feam-terminal:w1
```

Use a dedicated native Linux builder/disposable guest daemon; do not use the
physical host's unrelated daemon. Record the resulting image/config/archive
SHA-256 and native binary digest. [native_web_build.sh](scripts/native_web_build.sh)
builds and tests the Go service in the existing bounded native engineering scope;
invoke it by absolute path under `systemd-run --user`.

Load the approved image into the dedicated runner daemon and provide
`feam_image_id`, `feam_proxy_source` (remote native artifact),
`feam_proxy_sha256`, `feam_parent_uuid`, and the existing SSH operator's numeric
`feam_operator_uid` before deployment:

```bash
ansible-playbook -i PRIVATE_INVENTORY infra/demo/ansible/deploy-w1.yml
```

The deployment explicitly initializes only an empty slice; missing state with
existing containers or slot bytes fails for operator reconciliation. Normal
`start` never initializes state. The deployment generates one private gateway-owned credential; a repeated
apply preserves it. It starts the fixed container with no network, UID 1000,
read-only root, dropped capabilities, no-new-privileges, default seccomp,
512-MiB memory/no extra swap, 0.5 CPU, 128 PIDs and bounded tmpfs/descriptors/logs.
All terminal arguments are server-selected; ttyd URL arguments stay disabled.
The image initializes `/workspace/demo` at its final path and refuses partial
initialization. Its provider symlink and `client with spaces` path remain intact.

## Private browser and verification

Only the named SSH operator gets an ACL to the private frontend Unix socket.
The browser credential remains outside the container. Forward it from MAC:

```bash
ssh -o StrictHostKeyChecking=yes -o ExitOnForwardFailure=yes -N \
  -L 127.0.0.1:18771:/run/feam-w1-proxy/http.sock OPERATOR@PRIVATE_HOST
python infra/demo/tests/w1/browser_smoke.py \
  --credential-file PRIVATE_CREDENTIAL_FILE --output PRIVATE_BROWSER_RESULT
```

Use username `operator` and the private generated credential in a manual browser.
The proxy only accepts `http://127.0.0.1:18771`, filters request/response headers,
rejects URL arguments and permits two WebSocket connections. It never listens on
TCP or receives participant identity claims. Public DNS/Tunnel/Access are W8.

Inside the constrained image, run `python /opt/feam/image_smoke.py` for the real
SDK LazyFrame, known Rasterio window and final-path symlink. Run the installed
SDK tests with `FEAM_E2E=1`; the protocol tests that execute synthetic temporary
binaries require a separate test-only executable tmpfs. Runtime mounts remain
noexec. The [image walkthrough wrapper](tests/w1/image_walkthrough.py) uses a
symlink to the immutable installed binary for the existing manual/fake PTY
walkthrough; all its assertions and local review choices are unchanged.

[container_probe.py](tests/w1/container_probe.py) deliberately triggers one
bounded OOM, the PID ceiling and CPU throttling inside the disposable container.
[socket_probe.py](tests/w1/socket_probe.py) verifies gateway allowance and
other-identity denial. [mount_faults.py](tests/w1/mount_faults.py) refuses any
host except the named disposable QEMU guest: it tests missing/wrong mounts,
underlying-directory denial and runner restart without login, preserving UUIDs.
Never run this fault fixture on the physical host.

Operator lifecycle is a fixed, serialized W1 helper:

```bash
sudo /usr/local/sbin/feam-w1-terminal status
sudo /usr/local/sbin/feam-w1-terminal stop
sudo /usr/local/sbin/feam-w1-terminal start
sudo /usr/local/sbin/feam-w1-terminal reset --confirm-generation 1
```

Stop/start preserves files. Reset requires the exact generation and uses the
empty recorded spare; it retains the old stopped generation and never deletes
bytes. A second reset refuses an occupied spare. W3 owns participant-facing
review, allocation and retention. The physical-host reboot gate remains later
and needs an approved window.
